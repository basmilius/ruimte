# The canvas

The invariants of this folder. The repository root's `CLAUDE.md` has the map, the wire protocol and the rules that hold everywhere.

- A canvas has one state a person sets, the selection (`apps/client/src/state/canvas.ts`): a node is selected to be moved or removed. Beside it `bodyFocusId` says which node's content has the keyboard, which is what a page, a terminal and the wheel read (`isNodeActive`). A press in a body hands it over, and so does a press on a header, the way a title bar gives a window the keyboard (`apps/client/src/canvas/frame-press.ts`); a group has no content to type in and a press that adds to the selection is about moving nodes, so those leave it on the canvas. Escape takes it back to the canvas and keeps the selection, so the keys that act on a node work again. Every node drags, resizes and closes whatever either one says. Nodes are stacked with a z-index and never reordered in the DOM, or a click that brings one to the front takes the keyboard away from what it just landed in.
- A connector belongs to the canvas, never to a node: the line, the dots at its ends and the ports a node offers a pointer that comes near one are all drawn in the layer under the nodes (`apps/client/src/canvas/edge-route.ts`, `canvas/PortHints.tsx`). A line stops a gap short of the node it points at, and it routes around whatever lies between, a group excepted, since a group is a frame under its own nodes. It runs between the sides the two nodes face as long as that line is clear; one that has to go round takes the pair of sides that costs the least, counting its turns and every node it would squeeze past. An end drawn from a port keeps that side (`fromSide`, `toSide` on the edge), and an end nobody drew from stays free.
- A node resizes from a handle the canvas offers outside its frame (`canvas/ResizeHandles.tsx`, `canvas/resize-handles.ts`), never from its own edge, so a terminal, a page or a chat keeps every pixel of its content. Like a port it shows only while the pointer is near and outside every node that lies above it, one at a time on the nearest node, with or without the focus on it; the band of a selected node wins over the body of any node. A pill follows the pointer along an edge and gives way to the port in its middle; near an end, or on an edge too short for a pill, it bends into the corner, one path for every shape so it moves rather than swaps.
- What a line wears says what it is for (`canvas/edge-look.ts`): a context line is drawn in the accent with a dot at the end that reads, an origin line is the thin dashed one under the rest, and a target line is neutral with its point in the node being worked on. Between an agent and a page or a device the direction says nothing, since only the agent can read or work there: such a line is a target line whichever way a person drew it, and its point stays at the page or the device.
- What the canvas draws beside a node from that node's data is a derived card (`canvas/DerivedCards.tsx`, `canvas/DerivedSet.tsx`), never a node in the store and never written to the project: a routine's runs and its Output, and the workflow a chat node runs (`chat/workflow`). Which card is open is the window's alone, in memory per machine, view and node; only a size a person dragged is kept, in `localStorage`. A chat node on another machine reads that machine through `NodeMachineScope`, and draws no cards for a machine this client does not know, since the scope would fall back to the workspace's own. While a card beside a node holds the keys, the node's own content (a chat's composer) does not take them back.
