# The canvas

- A canvas has one state a person sets, the selection (`apps/client/src/state/canvas.ts`), of nodes to move or remove. Beside it `bodyFocusId` names the node whose content has the keyboard, which a page, a terminal and the wheel read (`isNodeActive`). A press in a body hands it over, and so does a press on a header, like a title bar (`frame-press.ts`). A group has no content, and a press that adds to the selection is about moving nodes, so both leave the keyboard on the canvas. Escape returns it to the canvas and keeps the selection, so node keys work again. Every node drags, resizes and closes on either state. Nodes stack by z-index and are never reordered in the DOM, or bringing one to the front would take the keyboard from what it just landed in.
- A connector belongs to the canvas, never a node. The line, its end dots and the ports a node offers a nearby pointer are drawn in the layer under the nodes (`edge-route.ts`, `PortHints.tsx`). A line stops a gap short of its node and routes around what lies between, except a group, which is a frame under its own nodes. It runs between the facing sides while that line is clear; otherwise it takes the pair of sides that costs least, counting turns and every node it squeezes past. An end drawn from a port keeps that side (`fromSide`, `toSide` on the edge); an end nobody drew from stays free.
- A node resizes from handles the canvas offers outside its frame (`ResizeHandles.tsx`, `resize-handles.ts`), never from its own edge, so a terminal, page or chat keeps every pixel. Like a port, a handle shows only while the pointer is near and outside every node above it, on the nearest node only, focused or not; a selected node's band wins over any node's body. A pill follows the pointer along an edge and gives way to the middle port. Near an end, or on an edge too short for a pill, it bends into the corner, one path for every shape, so it moves rather than swaps.
- A line's look says its purpose (`edge-look.ts`). A context line is accent with a dot at the reading end. An origin line is thin, dashed and under the rest. A target line is neutral, with its point in the node being worked on. Between an agent and a page or device direction means nothing, since only the agent reads or works there: such a line is a target line however it was drawn, with its point at the page or device.
