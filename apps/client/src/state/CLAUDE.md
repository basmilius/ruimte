# Client state

The invariants of this folder. The repository root's `CLAUDE.md` has the map, the wire protocol and the rules that hold everywhere.

- State about a machine is keyed on it: `${endpointId}:${nodeId}` is written only in `apps/client/src/state/keys.ts`. A machine is keyed on the id it mints, never on its address.
- Attention is counted once in `apps/client/src/state/attention.ts`, and `state/agent-work.ts` defines "working". Everything that shows a number reads those. The shell never counts.
- Every window is a page of one origin and shares `localStorage` with the others. A key a person means for the whole app (the machines, the settings, the theme) is read again when another window writes it (`state/shared-storage.ts`); a new key of that kind joins the list there. What a window keeps for itself (the open view, the camera, the panels) stays per page.
- A loose view (a file, a diff, a commit, a database view) stands in the layout under its tab key and has no row in the sidebar or in `project.json`. The layout owns where it stands and which tab is in front, `state/files.ts` owns what it shows, and the pool never holds one the layout does not place: a loose view that leaves a cell leaves the pool (`pruneLoose`), and the other way round every open goes through `showLoose`. The layout is loaded before the panels, since the pool of a project is whatever its layout places.
- Closing a cell, the other cells or the cells to the right goes through `state/cell-close.ts`, which closes the loose tabs one after another through their own questions (an unsaved file saves first, a table with unsubmitted edits asks) and stops when a person keeps one. The pure grid operations on the document (`closeCellAt` and the like) do not ask anything. The loose bodies of a host stay mounted, hidden, while a view of the project is in front of them, or a table would lose its unsubmitted edits to a switch of tab.
- A table can be a view of the project (`database` in `project.json`, kept from a loose tab through `promoteLooseDatabase`), and it draws the same body as the loose tab. `useFiles.unsubmitted` is keyed on either the loose key or that view's id, so closing its tab or its cell asks through the same dialog; only a person's `project.save` shares one, and not while its connection is private (`database/view-sharing.ts`).
