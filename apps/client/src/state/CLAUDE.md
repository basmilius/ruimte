# Client state

- State about a machine is keyed on it. Only `keys.ts` writes `${endpointId}:${nodeId}`. A machine is keyed on the id it mints, never its address.
- Attention is counted once in `attention.ts`, and `agent-work.ts` defines "working". Everything showing a number reads those; the shell never counts.
- Every window is a page of one origin and shares `localStorage`. A key meant for the whole app (machines, settings, theme) is read again when another window writes it (`shared-storage.ts`); a new key of that kind joins the list there. What a window keeps for itself (open view, camera, panels) stays per page.
- A loose view (a file, diff, commit or database view) stands in the layout under its tab key, with no sidebar row and no place in `project.json`. The layout owns where it stands and which tab is in front; `files.ts` owns what it shows. The pool never holds one the layout does not place: a loose view leaving a cell leaves the pool (`pruneLoose`), and every open goes through `showLoose`. The layout loads before the panels, since a project's pool is what its layout places.
- Closing a cell, the other cells or the cells to the right goes through `cell-close.ts`. It closes the loose tabs one by one through their own questions (an unsaved file saves first, a table with unsubmitted edits asks) and stops when a person keeps one. The pure grid operations (`closeCellAt` and the like) ask nothing. A host's loose bodies stay mounted, hidden, while a project view is in front, or a table would lose unsubmitted edits on a tab switch.
- A table can be a project view (`database` in `project.json`, promoted from a loose tab through `promoteLooseDatabase`), drawing the same body as the loose tab. `useFiles.unsubmitted` is keyed on the loose key or the view id, so closing either asks through the same dialog. Only a person's `project.save` shares one, and not while its connection is private (`database/view-sharing.ts`).
