# Changes to the API

<p className="lead">What changed in the extension API, and what to change in an extension that was written before.</p>

API version `1` is a preview. It goes to a small group of invited developers first, and it can still change before Ruimte offers extensions to everyone. Every change lands on this page, newest first, with what an extension has to do about it.

## 1, preview, agents, the canvas and settings (November 2026)

- `useAgent` reads one agent: its status, what it works on (`activity`), whether a wait was `snoozed`, and its folder and branch. Its `provider` can now be `null`. A chat or a design started on the default CLI has none until it reports which CLI it runs on. A terminal has an agent only once its CLI reported, so its `provider` is never `null`. In the test host an agent's `provider` is `null` unless the test names one, where it was `'claude'` before. `useSubagents` lists a chat's sub-agents at work, and `useProviders` the agents a person can start. The first two need `agents.status`.
- `defineCanvasOverlay` takes `space: 'canvas'`, to draw over the nodes in the canvas's own coordinates. On screen, `data-canvas-floor` marks what stands at the bottom of the canvas.
- `useCanvasView`, `useInView` and `nodeColorValue` read what a person sees of the canvas. A node's `color` is one of Ruimte's accents or `null`, and `hidden` says a collapsed group hides it.
- The `viewAccessory` slot stands beside a chat or terminal open as a view of its own, and `views.focus` hands one the keyboard.
- `storage` reads and writes `computer` values outside a component, and follows them with `watch`.
- `useLocale` reads nested keys and plurals.
- `defineExtensionSettings` takes `section`, which Ruimte grants only to the extensions it ships itself for now.
- An extension that reads `provider` from `useAgent` handles `null`, and a test that counted on `'claude'` names the provider itself. Any other extension needs no change.

## 1, preview, chats and charts (November 2026)

- `Chat` in `@ruimte/extension/client` draws a chat of the machine, its thread and its composer, inside your own surface. It needs `agents.start`, and draws a chat of the project in front.
- `agents.start` takes a `folder`, on the client and in `server/`, and starts the chat in the project the machine knows there, as a view of that project. In `server/` it takes `folder` instead of `project`.
- `@ruimte/extension/charts` and `@ruimte/extension/agents-ui` hand you the charts and the pieces of a chat Ruimte draws with. A pack takes them from Ruimte instead of bundling them, so they follow the ADE CORE version of the Ruimte that loads the extension, with no promise between releases.
- `agents.start` takes `hidden`, for a chat you draw yourself with `Chat`: it stays in the project and out of the sidebar.
- An extension needs no change.

## 1, preview, first changes (November 2026)

- `getServer` calls the server part outside a component, such as in a command's `run`. An extension needs no change.
- `createTestHost` throws for an option or an answer it does not know. A test that gave `server` beside `answers` fails now, and passes again with `server` under `answers`, where it was always read.

## 1, preview (November 2026)

The first version shared with invited developers.

- Every call that can fail for an expected reason answers a `Result`, so an extension checks `ok` instead of catching.
- The client and the server part use the same shapes: `NodeRef`, `ViewRef`, `near`, and typed events on both sides.
- `@ruimte/extension/testing` runs an extension's client and server part without Ruimte: `createTestHost`, `render` and `createTestServer`.
- The store is not open yet. Share an extension as a `.rex` and install it with **Install from disk** in Settings, Extensions.
