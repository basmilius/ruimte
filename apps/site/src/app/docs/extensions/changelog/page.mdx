# Changes to the API

<p className="lead">What changed in the extension API, and what to change in an extension that was written before.</p>

API version `1` is a preview. It goes to a small group of invited developers first, and it can still change before Ruimte offers extensions to everyone. Every change lands on this page, newest first, with what an extension has to do about it.

## 1, preview, marks in the editor's margin (November 2026)

- `defineEditorDecoration` in `client/` marks lines beside the line numbers of an open file, in a kind Ruimte colors. It reads only: it is told which file and nothing of what is in it. It is a proposed part, `editorDecorations`, and takes no permission.
- An extension needs no change.

## 1, preview, languages (November 2026)

- `defineLanguage` in `client/` names the files of a language of your own and the TextMate grammar that colors them in the editor and the viewer. It is a proposed part, `languages`, and takes no permission.
- An extension needs no change.

## 1, preview, settings of a project (November 2026)

- `defineProjectSettings` in `client/` adds a section to the settings of a project, with fields Ruimte draws. `useProjectSetting` reads a field for the project in front, and `projectSettings.get` reads it in `server/`. It is a proposed part, `projectSettings`, and takes no permission.
- An extension needs no change.

## 1, preview, references and slash commands from the machine (November 2026)

- `defineReference` and `defineSlashCommand` also exist in `server/`. What they offer after `#` and `/` shows in every client of the machine, also one that did not load your `client/`. Both are proposed parts, behind the new permission `composer.provide`.
- The ones in `client/` stay as they are. An extension needs no change.

## 1, preview, live data for a chat (November 2026)

- `defineUiSource` in `server/` gives the blocks an agent writes in a chat live data of your extension, drawn by the components Ruimte has. It is a proposed part, behind the new permission `ui.provide`.
- An extension needs no change.

## 1, preview, notification channels (November 2026)

- `defineNotificationChannel` in `server/` delivers what Ruimte tells a person about their agents somewhere else. Ruimte decides when, as for a push to a phone, and a person turns the channel on under Settings, Notifications. It is a proposed part, behind the new permission `notifications.provide`.
- An extension needs no change.

## 1, preview, machine sources (November 2026)

- `defineMachineSource` in `server/` lists places where Ruimte can start a machine, and describes the programs that start one. Ruimte runs them after the person approved them, and the new machine joins the account through its own `ruimte login`. It is a proposed part, behind the new permission `machines.provide`.
- An extension needs no change.

## 1, preview, what a chat waits on (November 2026)

- `chats.inspect` reads what a chat runs on and whether it waits for an approval or an answer, with `chats.read`. In `server/` it is the machine action `chat.inspect`.

## 1, preview, launch sources and problems (November 2026)

- `defineLaunchSource` in `server/` lists launches Ruimte starts, each only after the person approved its command, folder, variables and fingerprint. It is a proposed part, behind `launches.provide`.
- `defineProblemSource` and `problems` in `server/` report problems that show with the editor's own and that agents read. Both are a proposed part, behind `problems.provide`.
- `files` is in `server/` as well, where `readText`, `list` and `watch` name the project.
- `onEvent` in `server/` hears `launch.status` with `launches.read`, and `project.opened` and `project.closed` with the new permission `projects.read`. It takes a third argument that narrows an event to one project.
- `launches.create` and `launches.edit` add and change a launch, with the new permission `launches.write`. Neither approves it.
- A launch in `launches.list` has a `source`, which is `null` for a launch of the project's own files.
- An extension needs no change.

## 1, preview, terminals and proposed parts (November 2026)

- `terminals.open` in the client now answers a promise. The machine makes the terminal and starts it, so a write right after it lands. An extension that read its answer without `await` adds one.
- `terminals.write` types into a terminal the extension opened itself, with the new permission `terminals.write`. Every other terminal answers `refused`.
- `terminals` is in `server/` as well, where `open` names the project.
- The manifest takes `provides` and `proposed`. A proposed part works under `ruimte extension dev` and can change in any release. An installed extension that names one does not load.
- `defineTerminalProfile` in `server/` adds a kind of terminal to the menu of a new terminal. It is the first proposed part, behind `terminals.profiles`.

## 1, preview, agents, the canvas and settings (November 2026)

- `useAgent` reads one agent: its status, what it works on (`activity`), whether a wait was `snoozed`, and its folder and branch. Its `provider` can now be `null`. A chat or a design started on the default CLI has none until it reports which CLI it runs on. A terminal has an agent only once its CLI reported, so its `provider` is never `null`. In the test host an agent's `provider` is `null` unless the test names one, where it was `'claude'` before. `useSubagents` lists a chat's sub-agents at work, and `useProviders` the agents a person can start. The first two need `agents.status`.
- `defineCanvasOverlay` takes `space: 'canvas'`, to draw over the nodes in the canvas's own coordinates. On screen, `data-canvas-floor` marks what stands at the bottom of the canvas.
- `useCanvasView`, `useInView` and `nodeColorValue` read what a person sees of the canvas. A node's `color` is one of Ruimte's accents or `null`, and `hidden` says a collapsed group hides it.
- The `viewAccessory` slot stands beside a chat or terminal open as a view of its own, and `views.focus` hands one the keyboard.
- `storage` reads and writes `computer` values outside a component, and follows them with `watch`.
- `useLocale` reads nested keys and plurals.
- `defineExtensionSettings` takes `section`, which Ruimte grants only to the extensions it ships itself for now.
- An extension that reads `provider` from `useAgent` handles `null`, and a test that counted on `'claude'` names the provider itself. Any other extension needs no change.

## 1, preview, chats and charts (November 2026)

- `Chat` in `@ruimte/extension/client` draws a chat of the machine, its thread and its composer, inside your own surface. It needs `agents.start`, and draws a chat of the project in front.
- `agents.start` takes a `folder`, on the client and in `server/`, and starts the chat in the project the machine knows there, as a view of that project. In `server/` it takes `folder` instead of `project`.
- `@ruimte/extension/charts` and `@ruimte/extension/agents-ui` hand you the charts and the pieces of a chat Ruimte draws with. A pack takes them from Ruimte instead of bundling them, so they follow the ADE CORE version of the Ruimte that loads the extension, with no promise between releases.
- `agents.start` takes `hidden`, for a chat you draw yourself with `Chat`: it stays in the project and out of the sidebar.
- An extension needs no change.

## 1, preview, first changes (November 2026)

- `getServer` calls the server part outside a component, such as in a command's `run`. An extension needs no change.
- `createTestHost` throws for an option or an answer it does not know. A test that gave `server` beside `answers` fails now, and passes again with `server` under `answers`, where it was always read.

## 1, preview (November 2026)

The first version shared with invited developers.

- Every call that can fail for an expected reason answers a `Result`, so an extension checks `ok` instead of catching.
- The client and the server part use the same shapes: `NodeRef`, `ViewRef`, `near`, and typed events on both sides.
- `@ruimte/extension/testing` runs an extension's client and server part without Ruimte: `createTestHost`, `render` and `createTestServer`.
- The store is not open yet. Share an extension as a `.rex` and install it with **Install from disk** in Settings, Extensions.
