# Tunnels

<p className="lead">A tunnel puts Ruimte's MCP and your dev servers on the internet, through your own Cloudflare account. A bot that runs somewhere else can then work in Ruimte as you.</p>

You need a domain on Cloudflare and an API token for it. You manage tunnels from the Ruimte app on the machine itself. Other windows show the state and change nothing.

<SettingsTunnels />

## Set up a tunnel

1. Open Settings, Tunnels.
2. Click **Install** if Ruimte does not find `cloudflared`. Ruimte downloads Cloudflare's official build, checks it against a checksum, and keeps it in its own folder. Where no build exists for your system, the pane says what to install yourself.
3. Click **Make a token**. Cloudflare opens its token page with Zone read, DNS edit and Cloudflare Tunnel edit already ticked. Make the token, copy it, paste it into Ruimte and click **Check token**. Ruimte asks Cloudflare whether the token works, then lists the domains it reaches.
4. Click **Create tunnel**. If the token reaches more than one Cloudflare account, pick the account first. Ruimte makes one tunnel for this machine, named `ruimte-` and the machine's name.

Ruimte keeps the token on this machine and sends it only to Cloudflare. It never shows the token again. **Remove token** forgets it. The tunnel and its records stay in Cloudflare.

If something goes wrong, the pane says what Ruimte was doing and what Cloudflare answered, with a **Try again** button.

<Note tone="warning">Cloudflare ends the encryption at its edge, so it can read everything that passes through a tunnel. That includes prompts, file contents, credentials and the cookies of a dev site. A bot you connect reads whatever it is told or asks for, too.</Note>

## Add a hostname

Every hostname sits on a domain from the list, so one tunnel can serve `shop.bmnw.nl` and `api-tunnel.passly.dev` side by side. Pick the domain, then type a label such as `shop`, or a full hostname inside that domain.

Ruimte adds a proxied CNAME to the tunnel and the hostname to the tunnel's settings in Cloudflare, so the dashboard shows what Ruimte shows. If the name already has a DNS record that Ruimte did not make, Ruimte refuses and leaves the record alone. Delete the record in Cloudflare or pick another name.

Removing a hostname deletes the record and the hostname Ruimte made, and nothing else. Ruimte changes no other tunnel and no other record on your account.

## Add a dev server

Under **Hostnames**, pick a port that one of your sessions listens on, choose the domain and label, and tick that you know anyone with the address reaches it. Nothing sits in front of a dev server. No login, no gate.

Each hostname has its own switch and its own choice for after a restart. A dev server stays off by default, because its port may hold something else by then. Set **Comes back on** for a server that always runs on the same port.

## Connect a bot to the MCP

1. Under **External clients**, turn on **External MCP**. Ruimte now listens on this machine, on a port of its own, and nowhere else. This works without a tunnel: a bot on the same computer uses the address shown there.
2. To reach it from outside, add an MCP hostname under **Hostnames**. Ruimte suggests a long random label, so scanners do not find it. The name protects nothing. A credential does.
3. Give the bot the address, ending in `/mcp`.

The bot connects in one of two ways.

A client that supports OAuth asks Ruimte for access. A window opens on your machine with the address the client comes from and a short code. The name the client gives itself comes after that, and Ruimte has not checked it, so trust the address. Check that the code matches the one on the client's page, choose what the client may do, and approve. Requests wait one at a time, and the client's page only waits until you do. It gives up after a few minutes.

A client that can only set a header gets a bearer. Click **New bearer** under External clients, name it and copy the secret. Ruimte shows it once and keeps a hash, so it cannot show it again. A bearer works on this machine without a tunnel. On the public hostname it works only if you tick that box, and it is the weaker form. The same secret then crosses Cloudflare on every request, and nothing notices a stolen copy.

## What a client may do

A client acts as you, and what it gets is set when you approve it or make the bearer.

| Choice | Default | Effect |
| --- | --- | --- |
| Reach | Work | Read looks at projects, canvases and tasks. Work also changes canvases and starts agents. Machine also runs launches, routines, browsers, devices, databases and computer use. |
| Projects | All | A client sees and changes only the projects you name. |
| Agents it starts run up to | Supervised | A mode wider than this is refused. |
| Ends | Never | A credential lasts until you revoke it, unless you set an end. |
| Let it answer approvals | Off | The client can run shell commands. See below. |

A client never types into a terminal, and a terminal's prompts stay where they are. It can read every terminal in the projects it may use. It cannot make a credential, change its own reach or open the tunnels.

<Note tone="warning">With **Let it answer approvals** on, the client can run shell commands on this machine. It approves the commands that terminals, launches and routines hold, and what it approves runs as you. It sees each command in full before it approves, and an approval holds only for the command it was shown. Supervised then limits nothing.</Note>

## Keep an eye on clients

Nothing expires unless you set it, so noticing is the way to stop a client. Under **External clients**, each credential shows its name, what it reaches and when it was last used. The trash button revokes it. The client loses access from its next request. Agents it already started keep running.
