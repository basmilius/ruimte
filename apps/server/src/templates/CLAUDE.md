# Editor templates

- A person's templates live in `$RUIMTE_HOME/editor-templates.json` (0600), never in a project. Being under the home, no client file request reads or writes it.
- A project's templates live only in `.ruimte/templates.json`, which a team commits, with no private twin since nothing in it is personal. `disabled` and `settings` are a person's and never written there.
- Any client of the owner edits a person's templates, not only the local secret, since a template executes nothing. No template request is on a peer's list.
- A client reads and writes a project's templates only while it holds the project. `template.changed` for a project goes to the clients holding it; for a person's templates, to every client.
- Agents only list templates and add new ones to the person's own set (`ruimte-context template list`, `template new`, `canvas/template-verb.ts`). `TemplateStore.addByAgent` marks the template (`addedBy`), changes and removes none, and never writes the project's file. It refuses a key (`template-key-taken`) that any enabled template of the same kind and a shared language has: the person's own, the agent's project's, and the built-in ones minus those the person disabled. So an agent never shadows what a person relies on.
- The daemon cannot load the editor, so the built-in keys are `BUILT_IN_LIVE_TEMPLATE_KEYS` and `BUILT_IN_POSTFIX_TEMPLATE_KEYS` in `packages/contracts/src/built-in-templates.ts`, which a client test holds against ADE CORE's lists. An ADE CORE release that changes a built-in template fails that test until the list follows.
- Templates execute nothing, and the daemon sends no template body off the machine. An agent listing templates reads the person's and the project's bodies, as it reads any project file.
- Every write goes against the revision the client read (`rev-conflict`). The revision also moves on an outside edit (a pull, a hand edit), found by the watcher or at the start of a write. Revisions count up from the daemon's start time, so one never repeats after a restart.
- A file whose `version` is newer than this build is refused (`templates-too-new`) and left untouched, never set aside. `template.list` still answers a person's own templates when only the project file is too new, with `project: null` and `projectTooNew: true`; writes to that file stay refused. A JSON file that breaks the schema is refused the same way (`templates-invalid`, `projectInvalid: true`) and left untouched, for both the project's and the person's, since a team commits it. Only a non-JSON file is set aside as `.corrupt-<timestamp>`.
- Files are read loose: an unknown key or entry is written back as it was, where it was. A template save changes only the fields it names, and the project file is written only when its text changes.
- The daemon checks the key, the body length and the languages (`template-check.ts`). It does not parse the body's snippet syntax; the editor does, and drops what it cannot expand.
