# Voice run by the daemon

`apps/server/README.md` ("Voice for a phone") says what the route does.

- The matrix is the limit: Voice runs only `DAEMON_VOICE_ACTIONS` (`packages/voice/src/matrix.ts`) with the fields `VOICE_FIELD_RULES` (`action-policy.ts`) allows, checked in `tool-executor.ts` before a call and again before a confirmation. A daemon handler for Voice refuses any other actor (`voiceOf`), and `action-policy.test.ts` fails when an action becomes reachable without a choice for or against it.
- The daemon decides who Voice acts for. Session, owner (connection and scene) and time zone are set at `voice.start` (`VoiceCaller`), never by the model or the phone; the actor is `voice:<sessionId>`. Only the starting connection and scene are honored and hear `voice.status` and `voice.activity`. Owning a session is not owning the machine.
- A session holds one current project, of this machine only: the one the phone names, else the one opened last, else none. Only `project.switch` moves it, to a project in use here (`openProjects`), releasing the old one first. Every handler reads the current project when it runs (`no-project` without one). A switch writes nothing.
- Audio is never kept or logged (`isAudioEvent` drops echoes first). No timeline line holds what a chat said, raw tool arguments, a transcript or a key. An unexpected error reaches the model as `tool-error`, never with its message.
- A chat Voice started is no orphan (`outbox/end-children.ts` passes over its opener), and ending the session ends nothing it started. Its ceiling is `supervised`, its depth 1, and the executor sets the start claim `voice:<sessionId>:<call_id>`.
- A start from Voice is an AI Chat, never a terminal, refuses a CLI without a chat, and is checked against the untrusted folders (`refuseUntrustedStart`): a CLI that cannot be kept from a folder another machine made is refused there.
- Following goes by turn id, with the ticket taken before the prompt or start and bound to the turn the chat names. Idle is never done. The follower only notes: it wakes no chat and answers no request.
- What a chat says is data: the prompts tell both models so, and no confirmation follows from it. The executor answers only a token the registry gave this session, after rechecking the current project and revision, and forgets an ended session's tokens (`ActionRegistry.forget`).
- Voice writes only through `chat.send`, `agent.start` (within the per-field bounds) and `chat.clear`. A clear asks the person first, every time, through `voice.activity` and `voice.confirm`, and the handler rechecks on the answer.
- The key is a person's. It arrives on the local secret (`POST /machine/voice-key`, `ruimte voice key set`, `voice.setKey`), is read from `key-store.ts` at every start, and rides only in the `Authorization` header to OpenAI, never in a URL, log, error, event or anything the phone gets.
- Language and voice are the machine's (`preferences-store.ts`), set by any client but another machine. A session takes the stored choice first and its start's only while none is stored.
- Every timer (start deadline, minute clock, context debounce, a new chat's first-turn deadline) runs on the injected `VoiceClock`, ends with the session and wakes no chat.
