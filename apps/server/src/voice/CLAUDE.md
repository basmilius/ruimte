# Voice run by the daemon

`apps/server/README.md` ("Voice for a phone") says what the route does.

- The matrix is the limit. Voice runs only what `DAEMON_VOICE_ACTIONS` (`packages/voice/src/matrix.ts`) names, with the fields `VOICE_FIELD_RULES` (`action-policy.ts`) allows. `tool-executor.ts` checks this before the registry sees a call and again before answering a confirmation. A daemon handler for Voice refuses any other actor (`voiceOf` in `src/actions/voice-actions.ts`), and `action-policy.test.ts` fails when an action becomes reachable for Voice without a choice for or against it.
- The daemon decides who Voice acts for. Session, owner (connection and scene) and time zone are set at `voice.start` (`VoiceCaller`), never by the model or the phone. The actor id is `voice:<sessionId>`. After the start only the connection and scene that started the session are honored, and `voice.status` and `voice.activity` go only there. Owning a session is not owning the machine; the key stays the local secret's.
- A session works in and holds one current project at a time. The phone may name where it starts; otherwise it starts in the project opened last, or in none. Only `project.switch` moves it, and only to a project in use on this machine (`openProjects`). The session lets go of the old project before it holds the new one, and tells the phone in `voice.status` and the model in a new context. Voice never acts on another machine. Every handler reads the current project when it runs; one that needs a project refuses with `no-project` while there is none. A switch writes nothing.
- Audio is never kept or logged. The sideband drops every echoed audio event before anything sees it (`isAudioEvent`), and no timeline line holds what a chat said, raw tool arguments, a transcript or a key. An unexpected error reaches the model as `tool-error`, never with its message.
- A chat Voice started is no orphan. Its lineage names the session as opener, which no project places, so `outbox/end-children.ts` passes it over when the project is indexed again, and ending the session ends nothing it started. Its ceiling is `supervised` whatever the host reports, it is depth 1, and the executor sets the start claim `voice:<sessionId>:<call_id>` over whatever the model gave.
- A start from Voice is an AI Chat, never a terminal, and refuses a CLI without a chat. Voice is no node and gives no `cwd`, so its session's folder is checked against the untrusted folders (`refuseUntrustedStart`); a CLI that cannot be kept from a folder another machine made is refused there.
- Following goes by turn id, never by the next turn that happens to end. The ticket is taken before the prompt or start and bound to the turn the chat names (the first turn of a new chat). Idle is never done. The follower only notes, like the push service: it wakes no chat and answers no request.
- What a chat says is data. The prompts tell both models so, a report quotes it as such, and no confirmation follows from it. The executor answers only a token the registry gave this session, first rechecking that the current project and its revision are those it was asked in. The registry forgets every token of an ended session (`ActionRegistry.forget`).
- Voice writes only by prompting a chat (`chat.send`), starting one (`agent.start`) or clearing one (`chat.clear`), as desktop Voice does; a start keeps the per-field bounds whatever the model asks. A clear asks the person first, every time, as desktop Voice does by default. The call's line carries the question and its token to the owner's scene in `voice.activity`, so the phone answers with `voice.confirm` as the model does with its control tool, and the handler reruns its checks on the answer. A clear releases what the follower followed in that chat.
- The key is a person's; the daemon only passes it on. It comes from the desktop app's settings (the shell hands it over on `POST /machine/voice-key`), `ruimte voice key set` or `voice.setKey`, all on the local secret. It is read from `key-store.ts` at every start and rides only in the `Authorization` header to OpenAI: never in a URL, log line, error, event or anything the phone gets.
- How Voice talks (language and voice) is the machine's, in `preferences-store.ts`, and no secret. Any client but another machine reads and sets it, and every client hears the change. A session takes the stored choice first, and what its start names only while none is stored, so two devices starting Voice on one machine speak alike.
- Every timer runs on the injected `VoiceClock`, ends with the session and wakes no chat: the start deadline, the minute clock, the context debounce and a new chat's first-turn deadline.
