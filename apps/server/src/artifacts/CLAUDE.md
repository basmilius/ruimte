# Output

- Bytes are read by artifact id and version id only (`artifact.get`, `bytes.read` kind `artifact`), a file by its index, never its name. `$RUIMTE_HOME/artifacts` is not in `OPEN_FOLDERS` (`src/fs/machine-home.ts`), so no `fs.*`, path `bytes.read` or `GET /fs/file` reaches the register. A file's `name` is a label and the name Copy to project suggests, never a disk path.
- The daemon writes provenance from the call's context (the caller's chat, active turn, open task, node, the chat's CLI and model, this machine), never from an argument, so an agent cannot set or claim it.
- A publish never shows half. Bytes go to `.staging` with fsync, the manifest is written, one `rename` moves the folder into place, and only then is `register.json` written durably. Every start clears staging and rebuilds the register from the version folders, so a version renamed but not registered gets registered.
- A version joins an artifact by its key, by its origin for a copy from another machine, or, for an agent's publish without a key, as a file of the same name its chat published before (`republished` in `artifact-store.ts`). Another chat's file of that name stays its own artifact.
- A save names a request id, kept per artifact, so a retry answers the version it already made. A full disk refuses with `disk-full` before or during the write and leaves older versions alone.
- Nothing deletes a version on its own and no retention rule is stored. Cleanup proposes at ask time. A confirm removes exactly the versions a person sent, checked again, and never the latest, a version copied into a project, or one a node is pinned to.
- A person may also remove an artifact or some versions directly after confirming (`artifact.remove`), including the latest, a copied or a pinned one. Removing the last version removes the artifact. The project copy stays, and a pinned node shows the removal. Each folder moves into `.staging` in one rename before the register is written, so a stop leaves it gone or whole and the next start clears it. Agents and peers never remove: the request is on no peer's list and behind no verb or action.
- An artifact node's reference (`artifact`) is one person's on one machine, so it lives in the private overlay (`OVERLAY_FIELDS`, `packages/contracts/src/project-split.ts`), never the shared file; a teammate's copy of the node shows it is not on their machine. A node pins a version only with `version`. Cleanup leaves alone the pins of every project the index knows (`ProjectIndex.pinnedArtifactVersions`). An artifact view (kind `artifact`, its node holding the same reference) is never shared (`viewShareRefusal` answers `stays-on-machine`), so it lives whole in the private file, and an agent cannot make one.
- Another machine reads only the Output of the project its link names (`handlers/peer-artifacts.ts`). A copy from one (`artifact.importFrom`, `artifact-import.ts`) is a person's. It goes through staging like any save, each file must match the size and hash in the other machine's manifest, its provenance is this machine's person, and `origin` keeps what the other machine recorded. The request id comes from the origin version, so a second copy answers the first; a copy of a newer version of the same origin joins the artifact the first made.
- Copy to project writes only inside the project folder, refuses an existing name (`wx`), and refuses a link on the way or at the target.
- No artifact content (titles, names, bytes) goes into an error, telemetry, a usage count or a push.
