# Language servers

`apps/server/README.md#language-servers` has the kinds, install locations and pins.

- The PHP and SQL servers come from `basmilius/language-server-php` and `basmilius/language-server-sql`. A development daemon builds the checkout beside Ruimte or its primary checkout (`../language-servers/php`, `../language-servers/sql`, or `RUIMTE_PHP_LANGUAGE_SERVER_SOURCE` and `RUIMTE_SQL_LANGUAGE_SERVER_SOURCE`); discovery never changes a repository. Otherwise, and always in a compiled daemon, Install takes the release pinned in `php-native-release.json` or `sql-native-release.json`, checked against checksum and version.
- The daemon alone owns a document's text and version. A change whose `baseVersion` is not the daemon's is refused as `stale-document`, and the client reopens the document whole. A path is a stored path and goes through `MachineHome` like `fs.read`.
- A document opens on every kind that serves it (`SharedDocument.kinds`, its language's kind first); `eslint` and `tailwind` join only in a project that calls for them (`activation` in `profiles.ts`). Completion, code actions and hover merge across servers (`merge.ts`); any other feature is the first offering server's.
- A merged call awaits the first server without a deadline; every other gets `MERGE_DEADLINE_MS` and is left out after it, so a slow addition never holds up the main server. A server that does not answer `initialize` within `INITIALIZE_TIMEOUT_MS` is ended and marked `crashed` (`server.ts`). These timers belong to a request under way and schedule nothing.
- TypeScript 7 lacks most quick fixes and every refactor, so the `typescript` kind runs a TypeScript 6 sidecar (`typescript-actions`). It starts lazily on the first code action, is asked only for its own actions, and its diagnostics are dropped. It waits `SIDECAR_START_DEADLINE_MS` on the first request and `MERGE_DEADLINE_MS` after.
- Vue stays on TypeScript 6, since TypeScript 7 has no plugin API. In a Vue project the scripts go to the `vue` kind, so only one tsserver runs. A project's own TypeScript wins over the pinned one when new enough (`ownNativeTypescript` in `profiles.ts`).
- The restart rule below is decided on the exit event, with `STABLE_AFTER_MS` as the minute; anything else is `crashed` until `language.restart`. Every process of a pair goes down and up together, and its diagnostics clear while it is down.
- File watching starts once a server registered for `workspace/didChangeWatchedFiles` (`file-watch.ts`) and ends with the last such server. Events settle in the watch seam's timer and go to each server filtered by its own patterns; nothing runs on a clock of its own.
- Each server runs one client command at a time, because LSP does not tie `workspace/applyEdit` to its command. The edit goes to that command's client (`language.edit`); the daemon never applies it. It is refused when no command of that client runs or the client stays silent 30 seconds. Rename edits from `workspace/willRenameFiles` follow `fs.create` and `fs.write` rules.
- `didSave` goes to a server only when `fs.write` wrote exactly the text the daemon holds for an open document (`LanguageHost.saved`); any other write is not the servers' document. `willSave` comes from the client (`language.willSave`) and never holds up a save. `willSaveWaitUntil` goes to the document's first server that offers it, since two servers' edits rest on the same text.
- A `window/showMessageRequest` waits without a timer for a client's `language.messageAnswer`; the first answer wins. It settles with null when its server leaves `ready` or `indexing`, when the project's last holder leaves, or when the project has no holder at the start. Only an error or warning notification reaches a person; every message is also a log line.
- A whole-project pull (`language.workspaceProblems`) runs only on a person's press, one call per process at a time. It skips files the process has open as documents, and a process that goes down takes back what it reported (`clearReports`). Nothing re-pulls on a clock or on `workspace/diagnostic/refresh`.
- Trace lines (`$/logTrace`) and message lines carry source text and what a person saw, so neither goes into a crash report (`LanguageLog.serverOutput`). `telemetry/event` is dropped. The trace value lives in memory; a daemon start begins at `off`.
- `window/showDocument` is answered only while a client's command runs on the server (the tie `workspace/applyEdit` has), and shown to that client alone. A `file:` document inside the project folder opens in that client's editor. An `http(s)` address reaches it only as an offer, answered no, and a person's press opens it. A file outside the project, `external: true`, `mailto:` and every other scheme are refused and logged. Pending Bas's confirmation as a product rule.
- An agent uses the servers through `AgentLanguage` (`agent-language.ts`) as its own client for one call. It never installs a server, and a file read against a connection agents may not use is refused whole (`database-access-off`).
- Work another machine sent (`UntrustedFolders.inFolder`: a project folder or document in it) gets no kind that runs project code (`runsProjectCode`: rust-analyzer, ESLint, Tailwind) and no server of a person's own. A project folder there runs the pinned TypeScript, never its own.
- A package set (`packages/<setId>`, `package-store.ts`) is immutable and shared. An install only links its `node_modules` to it, and nothing writes into a published set. Mutable storage (Intelephense's `storage`, caches) stays in the install's own folder. Removing an install goes through `removeInstallFolder`, which unlinks `node_modules` before `rm`, so it never reaches into a set. Only `PackageStore.collect` removes a set: one no install on disk refers to and no lease holds, and nothing when the disk cannot be read in full. A dangling link reads as not installed; Install repairs it. Adopting real `node_modules` trees runs in `load()` before any server starts and swaps a tree for a link only after every file proved identical.
- Ruimte reads the PHP server's owner manifests (`owner-*.json` in `storage/cache`) and never derives a cache file name. A cache pass (`php-cache.ts`) runs inside `StorageGate.hold`, and a `php-native` start awaits the gate first (`beforeSpawn`), so no PHP server starts during a pass. A pass never removes the cache of a folder a server is live in (`LanguageServer.live`, from the start of a start until every process exited), removes nothing when a manifest has an unknown format, and removes files without a manifest only while no PHP process runs. A checkout counts as vanished only after repeated `ENOENT` sightings over a week with no known project folder around it; any other probe result forgets them.
- A native server never fetches anything itself. Install downloads PHP's stubs, and the server starts with `storagePath` and `stubsPath`. Checkout discovery reads files and never runs a git command that changes anything.

## Product rules

Decisions the code cannot show. Do not reverse one without asking Bas.

- Language servers are installed, updated and set back to their previous version only when a person presses Install, Update or the previous version, never by an agent or a verb. A pin that moved with a Ruimte update never stops a server; it runs what it has until a person updates.
- The daemon runs them itself, one per project per kind, shared by every client of the project. A server that ends by itself after a minute of being ready is started again once, at once (decided on the exit, never on a timer). One that ends sooner, or whose restart ends within that minute, stays crashed until a person restarts it.
- A server starts with the first document that needs it and ends only when its project closes on the machine (or the daemon stops), so moving between files never restarts it.
- A server of a person's own (a command they typed) is saved only through a local secret request, which approves exactly that command, arguments and environment. It lives under `$RUIMTE_HOME`, never in a project file; no verb or agent adds or changes one.
