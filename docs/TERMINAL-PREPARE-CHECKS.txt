Review findings addressed:
- OSC/PTY bytes cannot establish an editor or cwd. Startup read receives no bytes
  until explicit user input; the test verifies its first consumed byte is X, not ESC.
- A prefilled zle-line-init buffer remains occupied after background forged OSC.
- A late precmd cd is observed at the actual ZLE query, not at an earlier prompt hook.
- At insertion the ZLE widget rechecks editor context, live cwd, empty BUFFER and
  pending/queued input on a session-specific authenticated non-PTY channel.
- Each editor cycle closes its descriptor. A test caught and corrected the initial
  zsocket -d misuse: only explicit exec {descriptor}>&- closes that descriptor.
- Late buffer/cwd changes, builtin read, continuation/vared, timeout behind a blocked
  widget, invalid credentials, repeated confirmations and cleared used input are tested.
- The browser tests use the actual AssistantRow/Markdown, workspace-host callback,
  person action registry, dispatcher and real zsh. Streaming and incomplete fences
  show no action and send no request. Previewing does not change the editor.
- The simulated remote owner receives the action while the active endpoint is local;
  there is no fallback. Busy/input changes after preview refuse preparation.
- Prepared text remains editable and creates no sentinel file until explicit Enter.

  => { state: 'known', cwd: string, revision: number } | { state: 'unknown' }

exit, disconnect and an input/editor race during observation return unknown.
