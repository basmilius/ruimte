# Ruimte

Terminals, agents and browsers on one infinite canvas. `README.md` has the principles. This file is the map and the rules the code does not tell you.

## Layout

Bun workspaces (`bun install` at the root). Shared config at the root: `tsconfig.base.json`, `.oxlintrc.json`, `.editorconfig`, `bun.lock`.

- `apps/client`: the React UI (Vite). Never imports Node or Bun APIs. Talks to a daemon only through the `Transport` interface. One window holds one or more workspaces, each a project on a machine (`transport/connections.ts`, `state/workspace.ts`). In dev Vite proxies `/ws` to the daemon.
- `apps/server`: the daemon (Bun). Owns sessions, PTYs, chats and persistence under `$RUIMTE_HOME` (default `~/.ruimte`). WebSocket API on `localhost:4210`. In dev (`bun dev`) it runs on `4211` with `RUIMTE_HOME` defaulting to `~/.ruimte-dev`, so it never meets an installed Ruimte; pair with `bun src/main.ts pair --port 4211`. Flags, hooks and on-disk layout: `apps/server/README.md`.
- `apps/desktop`: the Electron shell around the client, with the daemon beside it. Only a small, fixed set crosses IPC; `src/preload.ts` mirrors `apps/client/src/desktop/bridge.ts`, and every bridge method added after the first release is optional. The refresh token stays in the shell (`src/pulsar-store.ts`); the page only gets access tokens. Browser pages have their own preload (`src/guest.ts`). A packaged app on macOS and Linux runs the daemon as a background service (`src/service`); the dev app never touches launchd or systemd.
- `apps/ios`: native iPhone/iPad client, iOS 26, Swift. `project.yml` is XcodeGen input; the generated Xcode project and `Package.resolved` are committed for Xcode Cloud. Regenerate with `bun run --cwd packages/contracts generate:swift` and `xcodegen generate --spec apps/ios/project.yml`; `bun run check` verifies generated models and fixtures. See `apps/ios/README.md`. Continue implementation autonomously; device measurements remain explicit acceptance evidence.
- `apps/station`: the web client at `station.ruimte.app` (Cloudflare Worker with static assets, `IS_STATION` in `apps/client/src/station.ts`). No local machine there (`state/local-machine.ts`).
- `apps/pulsar-broker`: relays signals between ed25519 keys (Bun). Never reads an envelope and stores nothing. It hands out ICE servers, so no client or daemon holds a TURN secret. See its README.
- `apps/pulsar-worker`: the address book at `pulsar.ruimte.app` (Cloudflare Worker, D1): accounts, sessions bound to a key, machines, signed access statements, device links. See its README.
- `packages/contracts`: zod 4 schemas for every message on the wire and the types derived from them. Nothing else may define a wire shape.
- `packages/pulsar`: zod schemas for the wires to services outside a daemon (broker, WebRTC signaling, address book) and `BrokerPeer`. The bytes every signature covers live in `signing.ts`, each with its own prefix line so a signature for one purpose never verifies as another.
- `packages/drawing`, `packages/diagram`: the pure parts of a drawing and a diagram. No DOM, so the client, exports and the daemon draw the same picture.
- `packages/service`: launchd and systemd definitions and managers, shared by the desktop shell and `ruimte service`.
- `packages/npm`: the `ruimte` launcher and per-platform binary packages. Package manifests are generated by `scripts/build.ts`, never checked in.

## Wire protocol

One WebSocket (or the same frames over a WebRTC DataChannel), JSON frames validated with zod on both ends.

- Request: `{ id, type, payload }`. Reply: `{ id, ok: true, result }` or `{ id, ok: false, error: { code, message } }`. Event: `{ type: 'event', event, payload }`.
- `REQUEST_SCHEMAS` and `EVENT_SCHEMAS` in `packages/contracts` are the tables both sides derive `RequestMap` and `EventMap` from.
- `PROTOCOL_VERSION` (`packages/contracts/src/protocol.ts`) is bumped only for an incompatible change, and both ends refuse any other version.
- A session id is chosen by the client (the node id), so a node reattaches after a reload.
- `session.attach` answers with the serialized screen from `@xterm/headless`, then streams raw output. A client never replays history. A byte is in the screen or in the stream, never both.
- Agent status comes from the CLIs' hooks only (`POST /hooks/<kind>`, `apps/server/src/agents`), never from parsing output. A chat is the CLI's stream-json protocol, no SDK.
- Chat events carry a `seq` per chat and are logged (`apps/server/src/chat/chat-log.ts`), so `chat.attach` with `since` resumes.
- Bytes for an `<img>` or `<video>` come only from `useMachineUrl` (`transport/machine-url.ts`). No draw site knows whether the link is a socket or a direct channel.
- A direct connection that fails says why and never falls back to the socket.

## Invariants and seams

- State about a machine is keyed on it: `${endpointId}:${nodeId}` is written only in `apps/client/src/state/keys.ts`. A machine is keyed on the id it mints, never on its address.
- A project is `<folder>/.ruimte/project.json` with a monotonic `rev`; every write goes against the rev it read, and a conflict comes back as `rev-conflict`. Drawings and diagrams follow the same discipline in their own files.
- Local state (open view, camera, grid layout, panels) is per client and never goes in `project.json`.
- A view or node of a kind this version does not know is kept as kind `unknown` and written back unchanged. A new kind is only safe to write once the previous release already had that fix.
- A file node or view is a path, relative to the project folder and absolute outside it (`packages/contracts/src/stored-path.ts`). The bytes are the file system's; there is no store.
- A link to a machine opens only for a hold (`transport/workspace-hold.ts`, `ensureMachine`, an open machine dialog or usage page) and closes 30 s after the last one. Nothing else may open one: not lists, status dots, auto-registration or limit bars. Clients sit on `machineTransport(id)`, which never opens a link.
- The source address never grants access (behind a tunnel everyone is loopback). A local process proves itself with `$RUIMTE_HOME/local.key` (`apps/server/src/auth/local-secret.ts`); others use a paired ed25519 key or a signed statement. Only the local secret may mint a pairing link. The daemon never holds an account token.
- Agents change the canvas only through `ruimte-context <verb>`, parsed and validated on the daemon (`apps/server/src/canvas/verbs.ts`). Writes go through `ProjectStore.mutate`. A refusal is a 422 starting with `refused\t<code>\t<message>`.
- The daemon, not a client, starts the agents a verb creates: through a durable entry in `$RUIMTE_HOME/outbox` (`apps/server/src/outbox`) that survives a restart. A running turn is resumed from the outbox too. Session and chat managers create one id at a time.
- Tasks (`apps/server/src/tasks`) settle on the child's result and wake the parent through the outbox, triggered by chat observers, never a clock. The tasks of one `team --task` call (`batchId`) wake it once, when all of them settled.
- A child agent never gets a wider permission mode than its parent (`apps/server/src/canvas/mode.ts`); the ceiling rides on every `start-agent` entry. A `--worktree` agent gets its own worktree under `$RUIMTE_HOME/worktrees`, never removed automatically. A worktree merge (`apps/server/src/git/worktree-merge.ts`) runs in the checkout that has the target branch out, never stashes and never moves a ref behind a working tree; an agent merges only the worktree of a node it opened, into a checkout without tracked changes, and a conflict is taken back for it. An agent's merge only merges: the child keeps running and its worktree and branch stay until a person removes them.
- Stopping or deleting a node ends its descendants through an `end-children` entry (`apps/server/src/outbox/end-children.ts`); their threads and screens stay.
- A fork (`chat.fork`, `apps/server/src/chat/fork.ts`) copies the CLI's conversation at the click: a Claude transcript cut at the turn's `native.lastUuid` (format checked against Claude Code 2.1.273, refused otherwise) or Codex `thread/fork` with `native.turnId`. Its record is written before its node, its agent's note waits in the record's `preambles` (never on the wire), and its lineage entry has `relation: 'fork'`, so ending, capping or orphaning the original never touches it. A chat view forks into a chat view listed right after it (a node into a node, or a view after its canvas with `asView`), and a fork and its original with no canvas in common read each other through that lineage entry instead of an edge (`apps/server/src/context/fork-origin.ts`). A fork in a worktree puts its files to the tree its turn settled with (`checkpointAfter`) only in that new worktree, never in a shared folder; a fork into another CLI copies no conversation and gets a handoff preamble instead (`chat/handoff.ts`), in a mode no wider than the original's. A fork's summary is a turn of the fork with `summaryFor`; `SummaryCoordinator` only owes a `deliver-summary` outbox entry, whose handler draws the line back first and then writes the note (id `summary-<turnId>`, so it lands once) and a preamble in the original. A fork node deleted before anyone wrote in it takes its record and transcript copy along, never its worktree.
- A plan belongs to a chat, never to a project: `$RUIMTE_HOME/chats/<chatId>.plans.json` beside the record (`apps/server/src/plans/plan-store.ts`), gone with the chat or a clear of it and copied by a fork. It is written as operations on item ids at the latest rev, without a base rev: every operation names an id and is refused when that id is gone, and the daemon is its only writer. An agent never overwrites a status a person set, and nothing about a plan wakes an agent or schedules work.
- Attention is counted once in `apps/client/src/state/attention.ts`, and `state/agent-work.ts` defines "working". Everything that shows a number reads those. The shell never counts.

## Product rules

Decisions the code cannot show. Do not reverse one without asking Bas.

- No kanban view, ever. A canvas is not a scheduler either: no cron, loop or trigger nodes, no task queue with retries or dependencies between nodes. The one reaction is a finished task waking the chat that delegated it, once.
- Skipped on purpose: minimap, dictation, notch HUD, agent-to-agent messages through a PTY, managed accounts, terminal color schemes, SSH/WSL environments, MCP browser automation, cookie and theme import, telemetry, checkpoint restore, a folder or files node (not a file manager) and a video node (a browser node plays a file).
- Every shortcut needs a modifier. The only bare keys are a drawing view's tools, and only while no text is typed and no dialog is up.
- Never highlight the canvas grid in the accent color. Type: only the four sizes in `@theme`, no bracket sizes, nothing below 12px; Geist only for the wordmark, Kalam only for drawing text.
- A page in a `<webview>` does not pinch-zoom (Chromium scales only the top-most widget); a `WebContentsView` per page and `setZoomFactor` were weighed and rejected.
- The wire only gains optional fields, new requests and new events. Never a new `ChatItemSchema` member or enum value in a chat or push payload: the iPhone app validates `chat.attach` and `chat.history` whole.
- Agents cannot type into or close another node's session, start a command through a verb (only `agent` starts anything) or drive a browser; `--cwd` stays inside the project folder or its worktrees.
- Whatever the daemon enforces against an agent (depth, lineage, tasks) lives under `$RUIMTE_HOME`, never in `project.json`, which an agent with a shell can rewrite. An observer only notes; only the outbox acts. Nothing removes a worktree on its own.
- Nothing reads a vendor credential (keychain, `~/.codex/auth.json`, usage endpoints); plan windows come from the CLIs. A stuck process gets a warning, never a signal a person did not press.
- A page never sees a refresh token, a daemon never holds an account token, and accounts are never merged.
- A zustand selector that builds a new array or object per call loops forever under `useShallow`: select the object and derive with `useMemo`.

## Conventions

- TypeScript in the Bun workspaces, Swift in `apps/ios`. 4 spaces, LF; `.editorconfig` is the rule.
- American English in code, comments, commit messages and UI text. No em dashes or en dashes anywhere.
- Always curly braces, also for one-line early returns. No one-letter variable names except `i`, `e`, `x`, `y`.
- Arrow functions inside functions; class methods are never arrow properties.
- Comments explain WHY, never what the code already says.
- Keyboard shortcuts are bound on `window`, once: the window's own in `shell/app-shortcuts.ts`, anything acting on a project once per workspace in `canvas/canvas-shortcuts.ts` behind `isFocusedWorkspace`. Never per cell or per node.
- A new surface that draws data of its own gets an `ErrorBoundary` (`src/ui/ErrorBoundary.tsx`), keyed so it resets only while it holds an error.
- UI: only semantic tokens from `styles.css`, no raw colors elsewhere. Tooltips are `Tooltip` (`src/ui/Tooltip.tsx`), never a `title` attribute. Related icon buttons go in a `BTN_GROUP` (`src/ui/classes.ts`). Icons are Lucide through `Icon`; the only exceptions are file icons (`FileIcon`, `@pierre/trees` with its own colors) and provider marks (`ProviderLogo`). No fractional pixels; a `rem` or `em` must resolve to whole pixels.
- In anything a person reads (UI text, tooltips, errors, toasts, empty states) a daemon is a **machine**. Code, comments and docs say daemon.
- Tests: `bun test`, next to the code (`foo.test.ts`). No test in the default run depends on wall-clock timing, a real shell or a file watcher: use a fake (`FakePtyAdapter` in `apps/server/src/pty/fake-pty.ts`, an injected clock or watch, `jest.useFakeTimers()`) and await what the code resolves. A test that fails on a timeout is made deterministic or deleted, never given a longer timeout.
- Real shells, watchers, sockets or processes go in `*.integration.test.ts` (`bun run test:integration`), which cleans up its own processes. A real `git` fixture is fine; build it once per file (`apps/server/src/git/test-repo.ts`).
- `bun run format` and `bun run check` (typecheck plus oxlint in every workspace) pass before a commit. Conventional commits (`feat:`, `fix:`, `chore:`, `refactor:`, `test:`, `docs:`).
- Written from scratch. Do not copy code from any other product; sharing ideas and npm packages is fine.
